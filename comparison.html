⚡ Feasibility Check: Can Nool Add Entire's Command Surface via ARAM (DSL / WASM)?

Empirical evaluation of Nool's WebAssembly sandbox (nool-aram-policy-sdk), Invariants DSL, and runtime boundaries.

Verdict: Gate works · Provenance rule not enforced yet · CLI surface No
What ARAM (WASM & DSL) Actually Is

ARAM is a sandboxed verification predicate defined in wit/aram.wit: 

export validate: func(knot-bytes: list<u8>, k: knot, stage: lifecycle-stage) -> result<_, denial>;

It operates inside Wasmtime with strict fuel limits and a 16MB memory ceiling at specific pipeline stages (pre-propose, pre-solidify, pre-push). It evaluates proposed changes and returns Allow or Deny.

Why ARAM Cannot Directly Replicate Entire's CLI
  • No CLI Subcommand Routing: ARAM policies cannot inject new top-level commands like nool checkpoint list or nool session resume into the compiled binary.
  • No Live Agent Hooks: ARAM only executes when code lands. It has no hook into active agent turn loops (SessionStart, PreToolUse) to capture streaming tokens or bash calls.
  • Strict Sandbox Isolation: WASM modules have no network access, file system I/O, or child process spawning capabilities.

⚠️ Transparent Failure & Edge Case Disclosure (What Failed During the Benchmark)

A trustworthy benchmark must disclose where tools failed or hit limitations. Here are the 4 actual failures encountered during execution:

Nool Limitations Disclosed
  • 1. Same-symbol conflicts still need a human: In the sandboxed re-run, nool merge unioned two branches that each added a different method (authenticate_oauth / authenticate_saml) at the same spot — 0 markers, tests pass — where plain git conflicted. When both branches rewrote the same method body, it stopped with standard git markers (correct), but its semantic pre-check had printed "no same-symbol collisions" — a false negative.
  • 1b. Lease protection depends on agent identity: Agents that announce without distinct --agent-ids share the session identity, so a second exclusive announce supersedes the first rather than conflicting.
  • 2. Strict Configuration Governance Locks: Attempting to install a WASM policy while modifying nool.toml resulted in an explicit failure (CONFIG_CHANGE refused). Nool mandates changes to governance files be solidified separately.
Entire Limitations Disclosed
  • 1. Offline / Local Search Failure: Running entire search "OAuth2" failed immediately with could not determine current repository for search: remote "origin" not found. Semantic search currently requires a configured remote repository.
  • 2. Cloud Auth Requirement for Summaries: entire recap failed with Not logged in. Run 'entire login' to authenticate. High-level summaries require Entire cloud backend connectivity.

Plain git detects conflicts only reactively at merge time, requires manual resolution of <<<<<</=======/>>>>> markers, and provides no attribution or session capture. Same-symbol business-logic conflicts still need an agent or human — in the original run Antigravity unified them under direct instruction.

Conclusion on Trustworthiness

Neither tool is a silver bullet. Entire does not prevent collisions; Nool does not magically rewrite conflicting business logic without agent or human intervention. The conflict resolution in this test was accomplished by Antigravity under direct instructions to unify both protocols, verified by Python unit tests, and audited by both Nool and Entire.
